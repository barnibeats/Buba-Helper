# Развёртывание WIM-образа с файлом ответов: что выяснено на практике

Заметки по связке «захват образа → `dism /Apply-Image` → первый запуск с `unattend.xml`». Проверялось на Windows 10 IoT Enterprise LTSC 21H2 (19044) в Hyper-V.

## Где должен лежать файл ответов

Sysprep сам копирует файл из `/unattend:` в `C:\Windows\Panther\unattend.xml`. При `dism /Apply-Image` этого не происходит, поэтому файл нужно положить **в образ** (или на диск после применения):

- `Windows\Panther\Unattend\Unattend.xml` (его находит Windows Setup на этапах `specialize` и `oobeSystem`);
- `Windows\System32\Sysprep\unattend.xml` (его берёт `Start-Sysprep.cmd`, когда образ собирают в следующий раз).

Генератор умеет искать вшитые скрипты в обоих местах (первая команда `specialize`), поэтому достаточно любого из них. Если заменить файл ответов в уже готовом WIM, достаточно смонтировать образ (`dism /Mount-Image`), заменить три копии (`Panther\unattend.xml`, `Panther\Unattend\Unattend.xml`, `Sysprep\unattend.xml`) и сохранить (`/Unmount-Image /Commit`): повторный sysprep не нужен. Скрипты из `Setup\Scripts` при развёртывании перезаписываются извлечением из XML.

## Настройки по пользователям

- **Шаблон Default** (`HKU\DefUser`, твики «Интерфейс» и др.) применяется только к профилям, созданным после `specialize`. Профиль, который уже есть в образе, не меняется.
- Поэтому настройки, которые должны сработать у каждого пользователя и у уже существующих профилей, выполняются через **Active Setup** (`UserSetup.ps1`): один раз при первом входе пользователя, до запуска Проводника. Запуск идёт через `wscript RunHidden.vbs`, чтобы окно PowerShell не мигало.
- Встроенный Администратор определяется по SID, оканчивающемуся на `-500` (его имя зависит от языка системы: `Administrator` / «Администратор»).
- Для PowerShell Direct (`Invoke-Command -VMName`) имя учётной записи тоже локализованное: на русской Windows — «Администратор».

## Что не работает так, как кажется

- **Обои.** Политика «Фон рабочего стола» (`Policies\System\Wallpaper`) читается Windows из `HKCU`; из `HKLM` она игнорируется. Значения стиля в политике свои (0 по центру, 1 мозаика, 2 растянуть, 3 по размеру, 4 заполнение, 5 расширить), а в `Control Panel\Desktop` другие (`WallpaperStyle` 0/2/6/10/22 + `TileWallpaper`). Расширение файла не важно: картинку Windows определяет по содержимому.
- **Поле поиска на панели задач.** `SearchboxTaskbarMode = 0` в Default недостаточно: при первом входе Windows включает поле заново (onboarding). Помогает пометка `OnboardSearchboxOnTaskbar`/`OnboardSBEmode = 1` плюс проверка при каждом входе после запуска Проводника.
- **Центр обновления для отдельных пользователей.** Политика `DisableWindowsUpdateAccess` в `HKCU\Software\Policies` на тестовой машине не записалась самим стартовым скриптом (причина не выяснена), надёжно скрывает страницу значение `SettingsPageVisibility = hide:windowsupdate` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer` у этого пользователя (в `HKLM` оно скрыло бы страницу у всех). Обе настройки записываются.
- **Значок «Панель управления» на рабочем столе.** CLSID в `HideDesktopIcons\NewStartPanel`: `{5399E694-6CE5-4D6C-8FCE-1D8870FDCBA0}` (с другим CLSID значок не появляется). «Этот компьютер»: `{20D04FE0-3AEA-1069-A2D8-08002B30309D}`.
- **Папки в «Этом компьютере».** Скрываются значением `ThisPCPolicy = Hide` в `…\Explorer\FolderDescriptions\{GUID}\PropertyBag`; ключи принадлежат TrustedInstaller, поэтому скрипт сначала берёт владение (`SeTakeOwnershipPrivilege`). «Объемные объекты» живут в `…\Explorer\MyComputer\NameSpace\{0DB7E03F-FC29-4DC6-9020-FF41B59E513A}` — ключ удаляется.

## SQL Server и лицензии в образе

После sysprep имя сервера внутри установленного SQL Server (`@@SERVERNAME`) остаётся от эталонной машины; подключение по `127.0.0.1` не страдает. Программы с привязкой к имени ПК, SID или железу нужно активировать заново.

## Антивирус хоста при снятии образа

`dism /Capture-Image` читает файлы смонтированного образа через Защитник Windows на хосте. Если в образе есть файлы, которые он считает вредоносными (например, активаторы, keygen-подобные установщики), DISM завершится с ошибкой 225. Для снятия образа отключите защиту в реальном времени на время захвата и включите обратно.
