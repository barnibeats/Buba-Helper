# Ремонт загрузчика

Вкладка **«Ремонт загрузчика»** чинит загрузку установленной Windows 7, 8, 10 или 11 на дисках **GPT (UEFI)** и **MBR (BIOS / Legacy)**. Данные на разделах не стираются: меняются только загрузочные файлы, BCD, MBR/загрузочный сектор, флаг «активный» и (по вашему выбору) раздел EFI. Лучше всего запускать из WinPE; из работающей Windows чинить её же загрузчик можно, но программа предупредит.

Запуск сразу на нужной странице: `Buba-Helper.exe --mode repair [--page 0|1|2]`; безопасная проверка без изменений: `--dry-run` (команды только пишутся в журнал).

## Три шага

### 1. Система

Список найденных установок Windows (Vista и новее): буква, диск, таблица разделов (GPT/MBR), версия, разрядность. Версия определяется по номеру сборки `ntoskrnl.exe` (у Windows 10 версия внутри файла показывает 6.2, ей верить нельзя).

Под списком — **диагностика** выбранной системы:

- есть ли на диске EFI-раздел (GPT) или активный раздел (MBR);
- есть ли загрузочные файлы в самой Windows (`Windows\Boot\EFI\bootmgfw.efi` или `Windows\Boot\PCAT\bootmgr`);
- совпадает ли режим ПК (UEFI/BIOS) с разметкой диска (GPT при BIOS и MBR при UEFI без Legacy/CSM загружаться не будут);
- подсказки, что именно не так.

Windows 7 x86 и Windows 7 без SP1 по UEFI загрузиться не могут (нет `bootmgfw.efi`): программа это покажет.

Раздел без буквы и зашифрованный BitLocker в списке не виден.

### 2. Раздел загрузчика

Таблица разделов диска этой системы (номер, тип, размер, буква, файловая система, роль). Подходящий раздел выбран сам: **EFI (ESP)** для GPT, **активный** для MBR (если активного нет, раздел Windows). Раздел без буквы получает временную, после ремонта она снимается.

Для GPT-диска здесь же решается вопрос с EFI-разделом:

- **Нет EFI-раздела** — галочка «Создать EFI-раздел (300 МБ)» включена сама, дальше нужно выбрать, откуда взять место.
- **EFI-раздел есть** — по желанию «Пересоздать EFI-раздел в другом месте»: старый удаляется (вместе с загрузчиками других систем на нём), новый создаётся там, где вы укажете.

**Откуда взять 300 МБ** (каждая строка читается как «где встанет раздел — за счёт чего»):

| Вариант | Результат |
|---|---|
| В начале диска — за счёт свободного места | EFI встаёт первым; доступно, если перед первым разделом уже есть ≥ 300 МБ |
| В конце диска / в середине, перед разделом N — за счёт свободного места | EFI в конце свободного участка, чтобы не мешать расширять предыдущий раздел (самый удобный вариант) |
| В середине диска, сразу после раздела N — за счёт свободного места | EFI в начале свободного участка |
| В середине диска, сразу после X: — за счёт раздела X: | раздел NTFS уменьшается на 300 МБ (`shrink`), EFI встаёт следом за ним |
| В начале диска, дальше C:, затем остальное — за счёт раздела C: | **перенос системы**, см. ниже |

### 3. Параметры и запуск

- **Создать новый BCD** (старый будет удалён) и **«Сохранить копию старого BCD рядом»** (`BCD.bak_<дата>`); если новый BCD не создавать, запись этой Windows добавляется в существующий (мультизагрузка сохраняется).
- **Запасной `EFI\Boot\bootx64.efi`** (GPT): нужен ПК, у которых запись в NVRAM пропадает или не создаётся.
- **Код загрузки в MBR** (MBR): `bootsect /nt60 /mbr`, затирает GRUB и другие загрузчики в MBR. Загрузочный сектор раздела пишется всегда.
- **Сделать раздел активным** (MBR).

Сводка «Что будет сделано» и окно подтверждения показывают итог перед стартом.

## Что делает ремонт

1. Проверяет, что в самой Windows есть загрузочные файлы.
2. При необходимости создаёт (и/или удаляет) EFI-раздел и подключает временную букву.
3. Убирает (с копией или без) старый BCD и запускает `bcdboot <Windows> /s <раздел загрузчика> /f UEFI|BIOS`. Если `bcdboot` из WinPE не справился, пробует `bcdboot` из самой Windows (для Windows 7 без ключа `/f`).
4. Для BIOS: делает раздел активным, пишет загрузочный сектор и MBR (`bootsect.exe` берётся из `tools\`, WinPE или PATH, а если его там нет — из вшитой копии, если exe был собран с `assets\bootsect.exe`).
5. Для UEFI: пишет запасной загрузчик, проверяет наличие `bootmgfw.efi` / `bootmgr` и BCD, выводит в журнал список записей BCD (`bcdedit /enum all`).
6. Снимает временные буквы.

## Перенос системы: EFI → Windows → остальное

Если перед Windows нет свободного места, «сдвинуть» уже существующий раздел `diskpart` не умеет, а сырой перенос раздела на месте небезопасен (сбой питания посреди копирования уничтожит систему). Поэтому доступен другой путь через **WIM-копию**:

1. Windows сохраняется в `.wim` (`dism /Capture-Image`, по умолчанию с исключениями DISM: `pagefile.sys`, `hiberfil.sys`, `System Volume Information`) на другой том или на **временный раздел** в свободном месте диска; файл проверяется (заголовок, размер).
2. Программа спрашивает ещё раз («точка невозврата»). Если отказаться, ничего не меняется (временный раздел удаляется).
3. Удаляются раздел Windows, выбранный EFI и MSR в зоне переноса; создаются **EFI 300 МБ** в самом начале диска и **Windows того же размера** сразу за ним; остальные разделы остаются как были.
4. Копия разворачивается обратно (`dism /Apply-Image`), затем выполняется обычный ремонт загрузчика.
5. Временный раздел с копией удаляется; если копия лежала на существующем томе, файл остаётся (его можно удалить).

Условия: запуск из WinPE (работающую систему переносить нельзя); перед Windows нет других разделов, кроме EFI и MSR; для копии есть том NTFS/exFAT со свободным местом около «занято на Windows + 1 ГБ» либо столько же свободного места на диске.

Что не переносится и на что обратить внимание: точки восстановления и содержимое `System Volume Information`; после первой загрузки проверьте буквы других дисков (привязка букв идёт по идентификатору раздела, у нового раздела Windows он другой).

**Если что-то пошло не так после удаления разделов**, копия остаётся на месте, а в сообщении об ошибке и в журнале выводится готовая команда восстановления:

```bat
:: создайте раздел NTFS (diskpart), затем:
dism /Apply-Image /ImageFile:"<путь к .wim>" /Index:1 /ApplyDir:<буква>:\
bcdboot <буква>:\Windows /s <буква EFI>: /f UEFI
```

Прежде чем применять перенос к реальному диску, проверьте его на виртуальной машине и скопируйте важные данные на другой диск.

## Типичные ситуации

| Ситуация | Что выбрать |
|---|---|
| Windows не загружается после переустановки второй системы / «Reboot and Select proper Boot device» | Обычный ремонт, галочка «Создать новый BCD» |
| Пропал или повреждён EFI-раздел (GPT) | «Создать EFI-раздел», место — в конце диска / из свободного места |
| Windows 7 на MBR не стартует | Ремонт на MBR: активный раздел + `bootsect /nt60 /mbr` |
| Есть другая система (мультизагрузка), её нужно сохранить | Снять «Создать новый BCD»: запись только добавится |
| EFI-раздел стоит между Windows и свободным местом и мешает расширять диск | «Пересоздать EFI-раздел…», вариант «в конце диска»; если нужно именно в начале — сначала передвиньте Windows сторонней утилитой либо воспользуйтесь переносом через WIM |

## Ограничения

- Динамические диски и тома на нескольких дисках не поддерживаются.
- Создание EFI-раздела возможно только на GPT; на MBR загрузчик пишется в активный раздел.
- Windows XP и старше (загрузка через `boot.ini`) не поддерживается.
- Перенос системы работает с одним разделом Windows и не двигает другие разделы.
