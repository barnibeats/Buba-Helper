## [1.5.0] — 2026-10-29

### Добавлено
- Вкладка «Драйверы»: **принудительная доустановка драйверов при первой загрузке Windows** (галочка включена по умолчанию). Раньше драйвер только клался в хранилище Windows, и она не всегда привязывала его к карте (адаптер не появлялся). Теперь программа копирует выбранные драйверы в `Windows\BubaFix` и добавляет в офлайн-реестр одноразовую службу `BubaNetFix`; при загрузке она сама, от SYSTEM и до входа в систему, выполняет `pnputil /scan-devices` и `pnputil /add-driver /subdirs /install` (то же, что делает установщик драйвера в живой Windows), затем удаляет себя и папку. Отчёты не создаются.
- Ключ `--page N` для `--mode drivers` (открыть сразу на нужном шаге).
- `devtools/net-fix-offline.cmd`: офлайн-диагностика и починка сети установленной Windows из WinPE (необязательно).

### Изменено
- README: описание вкладки «Драйверы», автообновления и сборки на .NET 8, скриншот новой вкладки.

## [1.4.0] — 2026-10-28

### Добавлено
- **Один самодостаточный exe: .NET 8 вшит в файл** (≈ 70 МБ), поэтому программа запускается в WinPE без .NET Framework (раньше выдавала «To run this application, you first must install .NET Framework v4.0.30319»). Сборка: `build.cmd` → `dotnet publish` (нужен .NET SDK 8), проект `Buba-Helper.csproj`. В WinPE нет ICU, поэтому включён инвариантный режим глобализации; кодовые страницы (OEM 437/866 для вывода `diskpart`/`dism`) подключаются `CodePagesEncodingProvider`, а кодировка консольных утилит берётся из `GetOEMCP` (`OemEnc.cs`).
- Вкладка **«Драйверы»**: добавление драйверов в установленную Windows офлайн (`dism /Add-Driver`, Windows не запускается). Три шага: система → драйверы → запуск. Источники: драйверы из хранилища WinPE (сеть и дисковые контроллеры; подходящие по ID устройств этого ПК выделяются сами), папка с драйверами, **встроенный набор сетевых драйверов** (Intel I217–I219, I210/I211, Realtek 8168/8125), **поиск и загрузка из каталога Microsoft Update по ID устройства** (`DriverCatalog.cs`). Дополнительно: отключение быстрого запуска и удаление `hiberfil.sys` в офлайн-системе (устройства иначе могут не инициализироваться), просмотр драйверов системы и выдержка из `setupapi.dev.log`. Ключ `--mode drivers`.
- **Проверка обновлений при запуске**: программа смотрит последний релиз на GitHub и, если он новее, предлагает обновиться. Скачивается `Buba-Helper.exe`, сверяется SHA-256 из `Buba-Helper.exe.sha256`, файл заменяется после закрытия программы и она запускается заново (если папка с exe только для чтения — новая версия запускается из временной папки). Для приватного репозитория нужен токен (read-only): переменная `BUBA_GH_TOKEN` или файл `update-token.txt` рядом с exe. Отключить: `--no-update`.
- Встроенные сетевые драйверы (`assets/net-drivers.zip`) в репозиторий не входят: их собирает `devtools/make-net-drivers.ps1` (на сборке в CI — автоматически).

### Изменено
- Вкладки режимов в шапке сужают отступы сильнее, чтобы поместились шесть вкладок.
- `build.cmd` теперь собирает через `dotnet publish`, CI устанавливает .NET SDK 8.

## [1.3.0] — 2026-10-26

### Добавлено
- Вкладка **«XML в ISO/WIM»**: вшивает файлы ответов в образ. Источник — ISO или WIM; для каждого из двух файлов выбирается место: корень ISO (`Autounattend.xml`), внутрь WIM (`Windows\Panther\Unattend\Unattend.xml` и `Windows\Panther\unattend.xml`) или оба. Редакции WIM — все или выбранные. Новый ISO собирается через `oscdimg` (BIOS + UEFI, метка тома сохраняется, UEFI без запроса «нажмите любую клавишу» по умолчанию), либо остаётся подготовленная папка. Исходный образ не меняется; при сбое WIM размонтируется без сохранения, рабочая папка удаляется. Ключ `--integrate` делает то же без окна.
- Внутрь WIM можно положить `Start-Sysprep.cmd` (в `Windows\System32\Sysprep`); файл ответов для Sysprep, идущий внутрь WIM, дополнительно копируется туда как `unattend.xml`. Ключ `--sysprep-cmd`.
- В генераторе XML кнопка «Вшить в ISO / WIM» передаёт готовый файл (и `Start-Sysprep.cmd` для режима Sysprep) на эту вкладку.

### Изменено
- Вкладки режимов в шапке сужают поля вокруг подписей, когда не помещаются в окно.

## [1.2.0] — 2026-10-23

### Добавлено
- Вкладка **«Ремонт загрузчика»** (Windows 7, 8, 10, 11; UEFI/GPT и BIOS/MBR). Три шага: выбор установленной Windows (версия и разрядность по `ntoskrnl.exe`, диск, таблица разделов, диагностика: есть ли EFI/активный раздел и загрузочные файлы в самой Windows, совпадает ли режим ПК с разметкой) → выбор раздела для загрузчика из таблицы разделов диска (подходящий выбран сам; раздел без буквы получает временную) → параметры и запуск. Делает: `bcdboot` (BCD создаётся заново (старый сохраняется как `BCD.bak_…` или, если снять галочку, удаляется без копии), либо запись добавляется в существующий BCD), запасной `EFI\Boot\bootx64.efi`, для BIOS — флаг «активный», `bootsect /nt60 [/mbr]`; при отсутствии EFI-раздела может создать его (300 МБ) за счёт раздела Windows. Данные на разделах не стираются. Ключ `--mode repair [--page N]`.
- Ремонт загрузчика: **выбор, откуда взять место под новый EFI-раздел** — неразмеченное место диска или уменьшение выбранного раздела NTFS. EFI встаёт в самое начало диска, если свободное место начинается там, иначе — в конец свободного участка (не мешает расширять соседний раздел). Новая галочка «Пересоздать EFI-раздел в другом месте» удаляет существующий EFI-раздел (`delete partition override`) и создаёт новый по тем же правилам; существующие разделы программа не сдвигает. `Native.GptUsable`, `Native.FreeSpans`.
- Ремонт загрузчика: вариант **«В начале диска, дальше Windows, затем остальное — за счёт раздела Windows»** (перенос системы через WIM-копию). Windows сохраняется в WIM (на другой том или во временный раздел в свободном месте диска) и проверяется; после повторного подтверждения («точка невозврата») удаляются Windows, выбранный EFI и MSR в зоне переноса, создаются EFI 300 МБ и Windows того же размера сразу за ним, копия разворачивается обратно (`dism /Apply-Image`), затем обычный ремонт загрузчика. Остальные разделы не трогаются. Доступно, только если перед Windows нет других разделов (кроме EFI/MSR) и запуск идёт не из этой же Windows. При сбое после удаления копия остаётся, команда восстановления выводится в сообщении.
- `bootsect.exe` можно вшить в программу: если рядом при сборке лежит `assets\bootsect.exe` (x64, ресурс `WinInstaller.bootsect.exe`), он используется, когда его нет в `tools`/WinPE/PATH. Работает и для ремонта загрузчика, и для BIOS-установки. Сам файл (Microsoft) в репозиторий не входит (`.gitignore`), `build.cmd` без него собирается как раньше.
- Версия программы в свойствах exe и в журнале (`src\AssemblyInfo.cs`), контроль версий в git: теги `vX.Y.Z`.
- `Native.Partitions`: чтение таблицы разделов диска (номера, тип, активный, GUID, буквы).

- Вкладка **«Установка Windows» переименована в «Установка ISO/WIM»** и дополнена: размер раздела Windows вводится в **МБ или ГБ** (по умолчанию ГБ), галочка **«Раздел восстановления (Windows RE), 1024 МБ»** (создаётся сразу после раздела Windows, `Winre.wim` копируется в `Recovery\WindowsRE` и регистрируется `reagentc /setreimage`; ключ профиля `recovery=1`), а из списка дисков для установки исключается **загрузочный носитель**: диск, с которого запущена программа, носитель WinPE/установочная флешка (`sources\boot.wim`) и диск текущей Windows.

### Изменено
- Вкладки режимов в шапке стали теснее, плашка «ПК: UEFI/BIOS» короче и не рисуется, если не помещается рядом с вкладками.

## [1.1.0] — 2026-10-23

### Файл ответов для образов (выявлено при развёртывании WIM через `dism /Apply-Image`)

#### Исправлено
- **Скрипты не извлекались при развёртывании образа.** Первая команда `specialize` читала `C:\Windows\Panther\unattend.xml`, а Windows создаёт этот файл до `specialize` только при `sysprep /unattend:`. Если файл ответов лежит в `Panther\Unattend\Unattend.xml` (как при `dism /Apply-Image`), команда молча падала, и не выполнялось ничего: твики, включение «Администратора», активация, программы. Теперь файл ищется в обоих местах (лимит команды 259 знаков соблюдён: `-nop -c` и подстановочные знаки в путях).
- **Мигание окна PowerShell и тексты ошибок при установке.** `RegSet` скрывал только обычный вывод `reg.exe`, поэтому ошибки (например, при удалении несуществующего ключа) выводились в окно. Теперь `2>&1`.
- **«Скрыть поле поиска на панели задач» не держалось.** Windows при первом входе включает поле поиска заново (onboarding). Твик теперь ещё ставит пометку «onboarding выполнен» и при каждом входе (без окна) проверяет значение, один раз перезапуская Проводник, если поле вернулось (Проводник только этого пользователя).
- Задача планировщика теперь может лежать в своей папке (`\IT\имя`), иметь лимит времени, перезапуск при сбое, запрет второго экземпляра и создаваться только если программа уже есть в образе.

#### Добавлено
- Новая страница редактора **«Рабочий стол и ярлыки»**:
  - обои из файла (путь, положение, запрет смены, чёрный фон вокруг картинки). Политика обоев Windows читается из профиля пользователя, а не из настроек компьютера, поэтому значения пишутся в шаблон Default и при первом входе каждого пользователя;
  - переименование ярлыков в меню «Пуск» (пары «Старое = Новое») и копирование выбранных на рабочий стол всех пользователей.
- На странице **«Защитник и безопасность»**: разрешающие правила брандмауэра для программ (пути к .exe и целые папки: правила строятся по найденным .exe) и для портов (входящие TCP/UDP, исходящие TCP, диапазоны), с необязательным добавлением найденных программ в исключения процессов Защитника.
- Новая группа твиков **«Образ и рабочее место (Buba-Helper)»**: запрет смены темы, цветов и фона для всех; значок «Провести собрание» убран; значки «Этот компьютер» и «Панель управления» только у встроенного Администратора; Центр обновления Windows скрыт и закрыт для всех, кроме встроенного Администратора; папки профиля (Видео, Документы, …) скрыты в «Этом компьютере».
- Настройки на уровне пользователя (Active Setup, запуск через `wscript` без окна): `UserSetup.ps1` выполняется при первом входе каждого пользователя до Проводника; встроенный Администратор определяется по SID `…-500`.
- `devtools/check-gen.ps1` и `docs/example-image-settings.json`: проверка генератора без установки Windows (XML, длина команды извлечения, синтаксис всех вшитых скриптов); запускается в CI.
- `docs/image-deploy-notes.md`: заметки по развёртыванию WIM-образа (где лежит файл ответов, Active Setup, политики, что не работает).

#### Изменено
- `devtools/gen-compare.js`: два намеренных отличия от оригинала (команда извлечения и `RegSet`) учтены при сверке; твик поиска выключается, так как расширен. Остальное по-прежнему сверяется посимвольно (430 случаев, 0 расхождений).
- Новые настройки по умолчанию выключены: если они не включены, результат совпадает с оригиналом.

### Добавлено
- **Генератор файлов ответов встроен в программу** (режим «Файл ответов (XML)»): `autounattend.xml` для чистой установки и `unattend.xml` для Sysprep, 13 страниц настроек (язык, установка и диск, система, пользователи, 70 твиков, Защитник, сеть, активация, удаление приложений, программы, скрипты, планировщик) и страница «Результат» с предупреждениями, предпросмотром и сохранением. Это порт [generator_XML_Windows](https://github.com/barnibeats/generator_XML_Windows) на C#; результат совпадает с оригиналом посимвольно (`devtools/gen-compare.js`).
- Быстрый старт «Windows 10 Pro без OOBE» и пресеты оригинала (дом, офис, приватность, разработчик, киоск).
- Кнопки «Использовать для установки» и «Использовать для захвата образа»: готовый XML сразу подставляется в нужное поле.
- Командная строка генератора: `Buba-Helper.exe --gen settings.json out.xml [--preset id] [--launcher Start-Sysprep.cmd]`.
- Пошаговый мастер (вкладки «Образ → Диск → Разметка → Настройки → Установка») с блокировкой незаполненных шагов и сводкой перед запуском.
- Новое оформление в духе игровых лаунчеров: тёмная плоская тема, режимы во вкладках сверху, шаги и страницы в боковом меню, карточки, акцентные кнопки, тёмные диалоги и полосы прокрутки. Все контролы рисуются кодом с двойной буферизацией (без мерцания), значки линейные, значок приложения встроен в exe.
- Адаптивная раскладка: окно можно менять от 960×640; карточки редактора XML тянутся по ширине, поля и подписи подстраиваются, горизонтальной прокрутки нет.
- XML ответов копируется и в `Panther\Unattend\Unattend.xml`, и в `Panther\unattend.xml`.
- Подсказка про Secure Boot / TPM для Windows 11 в сводке.

### Исправлено
- Редактор XML: после отметки галочки страница больше не «прыгает» наверх списка.
- Левое меню не мигает при наведении мыши и не оставляет «залипших» выделенных пунктов.

### Изменено
- Программа называется **Buba-Helper** (`bin\Buba-Helper.exe`).
- Исходники разбиты на файлы в `src/` (форма — `partial class`), сборка — `build.cmd`.

## [1.0.0] — 2026-10-11

### Добавлено
- Установка Windows из ISO / WIM / ESD: автопоиск образов, монтирование ISO через `virtdisk.dll`, запасная распаковка через 7-Zip.
- Выбор диска (Win32 API, без разбора вывода `diskpart`), защита диска-источника.
- Разметка GPT/MBR, размер раздела Windows вручную в МБ, раздел *Data* из остатка.
- Режим «только раздел Windows» — остальные разделы диска не трогаются.
- `dism /Apply-Image`, добавление драйверов, unattend XML, `bcdboot` (UEFI/BIOS), проверка загрузочных файлов.
- Проверка SHA-256 до изменения диска.
- Профили `.ini`, ключи `--profile`, `--auto`, `--yes`, `--dry-run`.
- Захват sysprep-образа в WIM: офлайн-проверка `GeneralizationState`, `/CheckIntegrity`, `.sha256`.
- Диалог с отсчётом перед перезагрузкой, звуковой сигнал.
